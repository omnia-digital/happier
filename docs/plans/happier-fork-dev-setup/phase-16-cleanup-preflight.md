# OH-52: Read-only host cleanup preflight

## Boundary

Implement a read-only decision over an existing verified phase14 worktree claim. The output describes independent worktree, local-branch, and temporary-directory skip reasons. This slice performs no cleanup, remote mutation, provider write, new machine capability, service action, or operation on a real checkout.

The host derives the active Home, server, release ring, and account from its canonical configuration and authenticated server profile. Its narrow input identifies the machine and launch nonce; the durable claim supplies the bound session. A path, PR, or session ID supplied by a caller cannot become a claim. Missing provider, publication, integration snapshot, inventory, or process proof remains a skip. Windows and Linux process completeness is not assumed from macOS observations.

## Deciding facts and implementation order

1. Preserve exact Git worktree identity and bytes through the existing checkout identity, porcelain worktree parser, status and repository owners. Capture tracked/staged/untracked/ignored, locked/prunable registration, operation state, default/protected branch state and all relevant refs without mutating them.
2. Require a fresh provider-qualified, merged, non-draft PR whose source head equals the current local branch HEAD and whose repository identity matches the claim. Require a real matching publication on the expected remote; a stale tracking ref or a deleted source branch is not proof. Merge, squash and rebase fixtures can establish only current PR state and publication. The available provider fields do not prove the source snapshot at merge time, so `integration_snapshot_unproven` independently blocks removal. Later local commits, remote movement and wrong repository skip.
3. Read fresh archived/inactive owner-session and other visible session/marker/process users through canonical owners. If the current source cannot prove exhaustive absence of other host users, retain `process_visibility_unknown` and do not return a deletion-ready decision.
4. RED/GREEN in disposable bare-origin and linked-worktree fixtures; fake only provider and authenticated server boundaries. Test each skip without modifying real resources. Check final result against races that a later executor must revalidate.

## Source observations during implementation

- `repository.ts` now uses actual linked checkout identity, realpaths, NUL porcelain status with staged/modified/untracked/ignored paths, and canonical worktree registration. Locked and prunable tokens are preserved by the existing parser. A clean status is only an observation; no removal permission is produced.
- `pullRequestOperations.ts` exact `get` rereads the provider and validates the linked PR identity. GitHub CLI's published `gh pr view --json` contract includes `headRepository` ([official field list](https://cli.github.com/manual/gh_pr_view)); REST has the source repository in `head.repo.full_name`. The canonical summary now preserves that optional field. An absent source repository, a fork source against the linked base repository, or GitLab payload without source identity skips. No provider registration or write is needed.
- Publication checks the live remote source ref and symbolic default HEAD with `git ls-remote`, not a stale remote-tracking ref. The exact source repo must match fetch and push remote identity. Deleted source refs skip because the current summary has no immutable deleted-branch publication proof. The local branch HEAD is re-read around the provider/remote lookups. `current_publication_match` carries `atMergeSourceHead: 'unproven'`; GitHub's current [`headRefOid` description](https://docs.github.com/en/graphql/reference/pulls) does not establish an immutable at-merge source snapshot. The normal/squash/rebase fixtures establish current publication and state, not that vendor guarantee. A later executor needs independent integration proof and immediate revalidation at its mutation boundary.
- `readHostWorktreeCleanupPreflight` reads the bound claim under canonical active Home/server/ring and the account returned by the authenticated server profile. Fixture server and scope overrides must be paired; production derives both from the same configuration. It requires the fresh V2 session to be archived, inactive, and machine/Home/path-consistent. Ordinary and archived visible sessions are paged; missing metadata/cursor/requests are incomplete. Both `other_session_uses_worktree` and `session_inventory_unknown` can be reported together. Other accounts, unrelated processes and branch protection are not exhaustively observable; `integration_snapshot_unproven` also independently blocks both worktree and local branch. Temporary directories have no phase14 claim. All three resource decisions are skipped. This is source evidence, not a cleanup capability.
- Focused CLI tests (10) and CLI typecheck passed after the canonical protocol build and bundled workspace declaration sync. Tests use disposable bare-origin and linked-worktree resources; provider/server boundaries are fixtures. No daily app, provider, or real checkout was changed.
