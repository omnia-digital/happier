## Bounded purpose

Discover the smallest host-owned safe cleanup implementation for phase10 slice3 while its independent Preferences/foreground autoarchive slice proceeds. This pass changes only this report; it does not implement cleanup or remove any real resource.

## Acceptance and boundaries

- Trace creation-time claims from UI/CLI checkout materialization through actual session ID binding and durable machine-owned storage. A path or linked PR alone is not ownership; existing unclaimed checkouts must stay safe.

- Identify canonical Git/filesystem owners and exact non-force primitives for independently eligible worktree, local branch and empty exclusively claimed temporary directory removal. Preserve remote branches.

- Report macOS/Windows/Linux differences honestly. No remote commands, installs, services, provider writes, account preference changes or daily native interaction.
- Propose decisive disposable-repository tests, auth/lifecycle seams and source decomposition; do not manufacture new claims or implement before the canonical lifecycle is understood.

## Source corridor and reachable gaps

**Creation and claim.** The UI calls machine SCM worktree creation before it has a session ID; `materializeNewSessionCheckout` returns path, session path and repository root, but no host provenance (`apps/ui/sources/components/sessions/new/modules/materializeNewSessionCheckout.ts:25-62`). `useCreateNewSession` then passes that path and a launch `spawnNonce`/attempt ID to `machineSpawnNewSession`, and receives the eventual session ID (`apps/ui/sources/components/sessions/new/hooks/useCreateNewSession.ts:869-926,1025-1047`). The daemon's nonce registry is process-local and TTL-bound, so it cannot serve as the durable ownership record (`apps/cli/src/daemon/spawn/daemonSpawnAttemptRegistry.ts:17-44,49-67`). The Git owner runs `git worktree add` and returns path/branch (`apps/cli/src/scm/backends/git/operations/worktreeOperations.ts:52-95,134-225`). Its `branchMode: 'existing'` creates a worktree on a preexisting branch and cannot claim branch ownership (`:104-128`). Existing manual SCM create without launch provenance and existing worktrees must remain unclaimed. `sessionWorkspaceLocationV1` only maps machine and agent paths; it is not a creation receipt (`packages/protocol/src/sessionMetadata/sessionWorkspaceLocationV1.ts:3-67`).

**Archive, machine and account authority.** The server archive route authenticates, requires admin, rejects an active session, and returns `archivedAt` after the transaction (`apps/server/sources/app/api/routes/session/registerSessionArchiveRoutes.ts:14-29,31-73,112-126`). Slice 2 will invoke cleanup only from the confirmed result of canonical `sessionArchiveWithServerScope`, shared by manual/bulk/automatic archive; a 409/failure never triggers cleanup. Host retry for an already archived session still requires a fresh read. The CLI can fetch `/v2/sessions/:id` with its token (`apps/cli/src/session/transport/http/sessionsHttp.ts:92-163`); the route queries only sessions visible to that user (`apps/server/sources/app/api/routes/session/registerSessionListingRoutes.ts:422-452`). Its mapper emits `share: null` for owner rows and a non-null share for a selected guest share, but also emits null if that selection is absent (`apps/server/sources/app/api/routes/session/v2SessionListRows.ts:255-311`). **Null alone is not an owner certificate.** The connected machine knows its authenticated account ID (`apps/cli/src/api/apiMachine.ts:455-459,1080-1115`), and generic machine RPC forwarding is same-user except delegated approvals (`apps/server/sources/app/api/socket/resolveRpcCallTarget.ts:17-57`). These are current transport facts, not yet a cleanup authorization proof.

**Actual child identity boundary.** `createSpawnedSession` dispatches the machine spawn RPC and recovers by nonce; it does **not** itself prove that a child created a server session (`apps/cli/src/session/services/createSpawnedSession.ts:483-540`). The child runtime calls `ApiClient.getOrCreateSession`, posting under its bearer token (`apps/cli/src/agent/runtime/initializeBackendRunSession.ts:373-381`; `apps/cli/src/api/api.ts:412-508`). The server looks up a tag only within `accountId: request.userId`, otherwise creates with that account ID, and returns `resolution: created | existing` (`apps/server/sources/app/api/routes/session/registerSessionCreateOrLoadRoute.ts:52-65,148-175,208-212,239-250`). The client currently uses the returned session ID but drops that resolution (`apps/cli/src/api/api.ts:503-555`). The daemon can correlate the child report to a tracked PID, adopt its reported ID, and persist a marker with cwd/nonce (`apps/cli/src/daemon/sessions/onHappySessionWebhook.ts:171-200,222-273,339-351`; `apps/cli/src/daemon/startDaemon.ts:3030-3055`). Its nonce resolver verifies the tracked runner, marker nonce, session ID and process fingerprint before settling readiness (`apps/cli/src/daemon/startDaemon.ts:2953-3019`), but it does not attest the server's `created` resolution or match the reported cwd to a pending cleanup claim. A resume takes `existingSessionId` and attaches to an existing row instead of creating one (`apps/cli/src/agent/runtime/initializeBackendRunSession.ts:248-330`); replay/source-context flows may also pre-create a row before runner spawn (`apps/cli/src/api/machine/rpcHandlers.ts:628-665`). Therefore **current code has no end-to-end, durable host-created session/worktree ownership proof**.

A future **machine-only** cleanup capability could avoid a new relay-admin method if the new host claim is bound through a child/server creation witness for the same authenticated account, nonce, runner and canonical path, and cleanup then requires a fresh archived/inactive owner-session read. The server's current owner-account filter is a useful basis; the host must retain a verified `created` witness or prior verified binding, not infer it from a caller-supplied ID, tag, webhook, path, `share: null`, or a later `existing` resolution. Until that witness and account/path checks are implemented, return `ownership_unproven`. The current session-write RPC set is only Stop/restart/transition and is edit-authorized (`packages/protocol/src/rpc.ts:204-209`; `apps/server/sources/app/api/socket/rpcHandler.ts:390-440`), so cleanup must not be added to it casually or use generic SCM remove. The CLI `setSessionArchivedState` may stop an active session on archive failure (`apps/cli/src/session/services/setSessionArchivedState.ts:25-73`); cleanup must not call it.

**Other users and processes.** The authenticated paged list has ordinary and archived endpoints; incomplete pages or undecodable encrypted metadata cannot prove absence of another session (`packages/protocol/src/sessionControl/contract.ts:317-332,380-387`; `apps/cli/src/session/transport/http/sessionsHttp.ts:263-313`). The connected-service retention owner already loops both lists and throws on incompleteness (`apps/cli/src/daemon/connectedServices/materialize/cleanup/listRetainedConnectedServiceMaterializationIdentityIds.ts:47-75`); reuse this inventory pattern, not its domain decision. Compare every visible session's decrypted machine/path mapping with the claimed realpath, including archived sessions. Other accounts' sessions may be invisible to this token, so the account list alone is not exhaustive host-user proof. Session markers contain session ID, cwd and PID, and `listSessionMarkers({requireComplete:true})` refuses invalid/unreadable markers (`apps/cli/src/daemon/sessionRegistry.ts:22-52,427-458`). `probeSessionRunnerPresence` distinguishes present, absent and unknown via tracked process and lock identity; plain `isSessionRunnerActive` collapses unknown to false (`apps/cli/src/daemon/sessions/isSessionRunnerActive.ts:105-165,194-224`). The generic process snapshot has PID/command and a short cache, but no cwd/open-file evidence (`apps/cli/src/daemon/processSnapshotCache.ts:1-51`). Terminal hosts, execution Runs, other accounts' sessions and unrelated shells/editors may use the checkout. No present cross-platform source owner proves exhaustive absence of those users; uncertain visibility must return `process_visibility_unknown` and keep the worktree. A macOS-specific read-only observer is acceptable only if a disposable fixture proves its target/process coverage; Windows/Linux remain unsupported until analogous evidence exists.

**Git and provider proof.** `inspectGitCheckoutIdentity` reads branch, HEAD, Git dir, common dir, worktree and registered path (`apps/cli/src/scm/backends/git/checkoutIdentity.ts:7-17,121-155`). The canonical snapshot reads status, worktree list, remotes, remote-HEAD refs and operation state (`apps/cli/src/scm/backends/git/repository.ts:62-154`), but normal status omits ignored files and the enrichment count is not deletion proof (`:68-74`; `apps/cli/src/scm/backends/git/worktreeStatusEnricher.ts:240-265`). The NUL-delimited worktree parser preserves odd path bytes but discards `locked`/`prunable` tokens (`apps/cli/src/scm/backends/git/worktreeListParser.ts:4-25,77-99`). Extend that owner or read its raw porcelain for cleanup. The current remove owner uses `git worktree remove --force` after only a nonempty-path check; UI spawn rollback also forces removal (`apps/cli/src/scm/backends/git/operations/worktreeOperations.ts:238-274`; `apps/ui/sources/components/sessions/new/modules/rollbackNewSessionArtifacts.ts:18-42`). Neither is an automatic cleanup primitive. `gitBranchList` lists local/upstream refs but has no delete (`apps/cli/src/scm/backends/git/operations/branchOperations.ts:144-195`). Preserve remote refs.

The PR summary has provider-qualified identity and optional `headSha` (`packages/protocol/src/scmPullRequests.ts:14-46,82-94`). The exact repository-qualified get verifies returned identity and propagates unavailable/auth errors (`apps/cli/src/scm/backends/git/operations/pullRequestOperations.ts:247-348`). GitHub/GitLab mapping distinguishes merged state and maps head SHA when supplied (`apps/cli/src/scm/hostingProviders/providers/githubPullRequestMapping.ts:14-47`; `gitlabMergeRequestMapping.ts:14-46`); the CLI views request these data (`githubCliAdapter.ts:26,106-124`; `gitlabCliAdapter.ts:84-108`). The open-list cache is not cleanup proof. The local HEAD must match a freshly verified merged PR's exact source head and be proven published to the linked repository, via a fresh matching remote ref or provider-backed immutable merged-source-head evidence if that remote branch was deleted. A merged PR alone, stale remote-tracking ref, original claim-time HEAD, or target-branch ancestry cannot establish that later local work was integrated. Squash/rebase must be eligible only with the same exact source snapshot and provider merge proof; Git target ancestry is not required. Current summary has no dedicated immutable merged-head/source-repository proof field, so deleted-remote cases may remain `integration_unproven` until the provider adapter contract is characterized and tested. Force-push, later local commits, missing head SHA, unavailable provider, wrong fork/remote, and changed association all skip.

## Smallest implementation seam for root decision

1. Pass the existing launch nonce into the **new-session** Git worktree create request. On successful `git worktree add`, the host Git owner records a machine-local pending claim *before* returning claimable success: version; account and machine IDs; nonce; canonical realpath and registered path; canonical Git common dir; branch; `branchCreatedHere` (false for `existing`); and optional explicitly created temp directory. The account ID must come from `ApiMachine.getAccountId()` through a host-owned scope dependency (`apps/cli/src/api/apiMachine.ts:455-459,1080-1115`), not the caller's request. Persist through the existing atomic/locked JSON-owner pattern (`apps/cli/src/daemon/sessionRegistry.ts:72-109,140-201`), but not in PID markers removed at process exit (`:412-425`). Claim write failure leaves the checkout for manual handling and returns unclaimable. This is an ownership record, not a claim inferred later from UI path or PR.
2. Bind that pending host claim to the actual session ID only after the child reports a server `resolution: created` for its authenticated account and the daemon correlates that child to the same nonce, runner identity, canonical cwd and machine. Persist this creation witness with the claim, then compare it with a fresh authenticated session read. A later `resolution: existing` can rejoin only a **previously verified, durable** binding for that same nonce/session; otherwise it is unclaimed. Explicit `existingSessionId` resume, pre-created replay/source-context, external terminal report, shared session and mismatched account/path are not new-session claims. The UI may request reconciliation after confirmed spawn but cannot mint the witness. Retry/reentry is idempotent; ambiguous nonce, lost pending record, mismatch or failed spawn never grants cleanup. Store per-resource completion so a removed worktree does not make a later branch retry interpret path absence as proof.
3. Expose one machine-only, session-ID-only cleanup capability. The host checks its account/machine claim and fresh owner/archived/inactive session, complete other-session and local marker/run/process inventory, canonical Git identity, clean tracked/staged/untracked/**ignored** status, no Git operation or lock, protected/default/main/ref checks, and fresh PR/push proof. Re-evaluate before **each** mutation. Use non-force `git worktree remove -- <registered-path>`; Git refusal is a failure, never a cue to force. Re-read worktree registrations, refs and publication proof before any eligible local branch delete; `git branch -d -- <name>` is valid only where ancestry itself suffices, while squash/rebase needs `git update-ref -d refs/heads/<name> <expected-oid>` after the stronger provider proof and a fresh unused/protected-ref check. That expected-OID argument is Git's compare-and-swap guard, not a force delete. A claimed temporary directory is removable only when exact canonical path/parent/inode still match and `readdir` is empty, using nonrecursive `rmdir`. The worktree-created `.worktrees` parent is not automatically claimed. A pathname check followed by Git/rmdir is still subject to a hostile concurrent path swap; the implementation must test this race and retain the path if its platform primitives cannot keep the checked directory identity through removal. No remote deletion.
4. Return independent `removed | skipped(code) | failed(code)` outcomes for worktree, local branch and temp directory. Offline host, missing capability, partial inventory, unknown process, auth mismatch, changed path/ref and provider uncertainty remain visible retryable skips or failures. Retry rereads live evidence; no stale pass receipt. Older CLI/relay combinations must report unsupported, not success. Slice 2's confirmed archive seam is the only scheduling source; no background cleaner, server filesystem owner, service install or daily-app change is justified by this evidence.

## Decisive disposable proof recipe (not executed in this discovery pass)

Use the existing CLI SCM RPC/testkit with an isolated temporary bare origin, checkout and linked worktree. Fake only provider and server auth/session boundaries. RED: a preexisting unclaimed checkout, forged UI path/session ID, wrong account/machine, shared guest session, missing/old capability, timeout before binding, changed nonce, server `existing` without a prior verified binding, explicit resume ID and unrelated webhook must all refuse removal. GREEN: actual child `created` resolution plus correlated runner/nonce/path binds and reloads one exact claim across daemon restart; the same nonce's later `existing` resolution may rejoin only that stored binding; `branchMode: existing` never claims its branch. Independently insert staged, modified, untracked and **ignored** files; another linked worktree; locked/prunable registration; main/default/protected ref; another ordinary or archived session; live runner/terminal/execution Run; inaccessible process; symlink/registered-path swap; Git failure immediately before mutation. Each keeps bytes and refs. In bare-origin histories, verify merge/squash/rebase with exact published source head, then add a later local commit, advance remote, delete source remote branch, or make provider read unavailable. Only a demonstrably unchanged, published and integrated snapshot qualifies. Inject a race between worktree and branch steps: branch stays; retry partial success without widening authority. Assert remote refs never change. Run macOS source tests and report Windows/Linux as skipped until their process/path proof is exercised.
